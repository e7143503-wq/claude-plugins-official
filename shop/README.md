# Бюро проектов: сайт для продажи готовых проектов

Витрина с каталогом, карточками проектов, корзиной и заявкой. Обычные HTML, CSS и JavaScript: без сборки, без зависимостей и без сервера. Работает на любом статическом хостинге и открывается прямо из файла.

## Как посмотреть

Откройте `index.html` в браузере. Или запустите локальный сервер из этой папки:

```bash
python3 -m http.server 4173
```

и зайдите на `http://localhost:4173`.

## Что где лежит

| Файл | Что в нём |
| --- | --- |
| `js/projects.js` | Каталог: все проекты, цены, описания |
| `js/config.js` | Название магазина, валюта, контакты, приём заявок |
| `index.html` | Тексты страницы: первый экран, шаги покупки, вопросы и ответы |
| `css/styles.css` | Оформление. Цвета и шрифты собраны в начале файла |
| `js/app.js` | Логика каталога, корзины и заявки. Менять не нужно |
| `favicon.svg` | Значок вкладки |

## Как добавить проект

Откройте `js/projects.js`, скопируйте любой блок в фигурных скобках и поменяйте значения. Обязательно только название:

```js
{
  id: "my-project",
  title: "Мой проект",
  category: "Сайты",
  price: 15000,
  summary: "Одна-две строки для карточки.",
  description: "Полное описание.\n\nВторой абзац.",
  features: ["Что умеет", "Что ещё умеет"],
  includes: ["Исходный код", "Инструкция"],
  stack: ["React", "Node.js"],
  specs: { "Лицензия": "Копия", "Передача": "1 рабочий день" }
}
```

Все поля описаны в начале файла `js/projects.js`. Самое полезное:

- `price: null` показывает «По запросу», `price: 0` показывает «Бесплатно».
- `oldPrice` больше `price` добавляет зачёркнутую цену и метку со скидкой.
- `sold: true` оставляет проект в каталоге со штампом «Продано».
- `image: "img/crm.jpg"` ставит свою обложку, `gallery` добавляет картинки в карточку. Без картинки обложка рисуется сама по категории проекта.
- `demoUrl` добавляет кнопку «Открыть демо», `buyUrl` добавляет кнопку «Оплатить онлайн».
- `id` попадает в ссылку на проект (`?project=my-project`). Задайте его один раз и не меняйте.

Категории в фильтре собираются из поля `category` сами. Порядок проектов в файле задаёт порядок в каталоге.

## Настройки

Всё в `js/config.js`:

- `brand`: название и подпись магазина.
- `demo`: пока стоит `true`, над сайтом видна плашка «Демо-каталог».
- `currency` и `locale`: валюта и формат цен, например `"USD"` и `"en-US"`.
- `contacts`: почта, Telegram, WhatsApp и телефон продавца.
- `orderEndpoint`: адрес, на который сайт сам отправляет заявки.
- `legal`: ссылки на политику конфиденциальности и оферту.

## Как покупатель оформляет заказ

Сайт не принимает оплату сам. Есть три способа получать заказы, их можно сочетать.

1. **Заявка через мессенджер или почту.** Работает сразу. Покупатель собирает корзину и заполняет форму, сайт составляет текст заявки и открывает Telegram, WhatsApp или почту с готовым сообщением. Нужен хотя бы один контакт в `contacts`.
2. **Заявка приходит сама.** Укажите в `orderEndpoint` адрес сервиса форм (Formspree, Getform) или своего сервера. Сайт отправит туда `POST` с JSON:

   ```json
   {
     "orderId": "1110-4821",
     "name": "Анна",
     "contact": "@anna",
     "comment": "",
     "items": [{ "id": "mini-crm", "title": "CRM для небольшой команды", "price": 85000 }],
     "total": 85000,
     "hasPriceOnRequest": false,
     "currency": "RUB",
     "message": "Текст заявки целиком",
     "page": "https://example.com/"
   }
   ```

   Если сервер не ответил, покупатель увидит способ из пункта 1.
3. **Прямая оплата.** Создайте платёжную ссылку в своём платёжном сервисе и укажите её в поле `buyUrl` проекта. В карточке появится кнопка «Оплатить онлайн».

## Публикация

Сайт статический: загрузите содержимое этой папки на любой хостинг.

- **Netlify, Vercel, Cloudflare Pages:** подключите репозиторий и укажите папку публикации `shop`. Команда сборки не нужна.
- **GitHub Pages:** сайт лежит в подпапке, поэтому нужен файл `.github/workflows/deploy-shop.yml`:

  ```yaml
  name: Deploy shop
  on:
    workflow_dispatch:
  permissions:
    contents: read
    pages: write
    id-token: write
  jobs:
    deploy:
      runs-on: ubuntu-latest
      environment:
        name: github-pages
        url: ${{ steps.deployment.outputs.page_url }}
      steps:
        - uses: actions/checkout@v4
        - uses: actions/configure-pages@v5
        - uses: actions/upload-pages-artifact@v3
          with:
            path: shop
        - id: deployment
          uses: actions/deploy-pages@v4
  ```

  Затем в настройках репозитория откройте Pages, выберите источник GitHub Actions и запустите workflow вручную на вкладке Actions.

## Перед запуском

- [ ] Заменить демо-проекты в `js/projects.js` своими.
- [ ] Указать свои контакты в `js/config.js` и убрать адрес-заглушку `hello@example.com`.
- [ ] Поставить `demo: false`.
- [ ] Перечитать тексты в `index.html`. Шаги покупки и ответы на вопросы написаны как пример: сроки, поддержку и условия лицензий укажите свои.
- [ ] Поменять название в `<title>` и описание в `<meta name="description">`: их читают поисковики и мессенджеры.
- [ ] Если сайт сам отправляет заявки (`orderEndpoint`), вы собираете персональные данные. Добавьте политику конфиденциальности в `legal.privacyUrl`: в форме появится обязательная галочка согласия. Точные требования зависят от страны.
- [ ] Отправить пробную заявку с телефона.

## Что стоит знать

- Корзина хранится в браузере покупателя и не теряется при перезагрузке страницы.
- У каждого проекта есть своя ссылка. Её удобно отправлять клиенту.
- Каталог рисуется скриптом. Поисковики, которые выполняют JavaScript, его увидят, остальные увидят только тексты страницы.
- Шрифты загружаются с Google Fonts. Без них сайт покажется системным шрифтом.
